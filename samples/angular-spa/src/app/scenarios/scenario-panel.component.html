S10 — Distributed tracing (outbound leg only)

`propagateTrace: true` + `tracePropagationTargets: ['/api/']` (FULL_LAUNCH_OPTIONS): the local API echoes back every header it received, so a `traceparent` header actually leaving the process is checkable in-sample. THREE probes fire, because same-origin alone cannot exercise the allowlist — the decorator allows any same-origin url before consulting it. (1) same-origin `/api/scenario/echo-headers` (proxied) — decorated, falsifies `propagateTrace`; (2) cross-origin `:5336/api/scenario/echo-headers` — matches `/api/`, must be decorated (the INCLUDE half); (3) cross-origin `:5336/echo-headers-unmatched` — no `/api/` in the url, must NOT be decorated (the EXCLUDE half). No second hop / backend join is attempted here.

S11 — Session replay

`@bugsee/replay` (+ `@bugsee/replay-canvas`) are transitive dependencies of `@bugsee/browser`, lazily imported whenever replay is enabled — which is by default: the browser tier records unless `replay: false` is passed, so the app's own baseline launch (no `replay` key at all) is already recording before any control below is clicked. What these controls change is the replay CONFIGURATION, not whether recording happens; `replay.bin` is therefore present in every bundle this app uploads, and only the `replay: false` control makes it disappear. `get_issue` does not expose replay CONTENTS, so the verification is local/wire (`replay.bin` presence, plus the decoded masking pair below).
