# Adversarial review — @bugsee/logger

**Reviewed:** 2026-07-26 · **Scope:** packages/logger (impl 85 LOC, tests 149 LOC)

**Verdict:** The implementation is clean, allocation-cheap and genuinely runtime-portable — zero imports, zero global access, no `node:*`/DOM references, so it runs identically on every target runtime. The test suite is unusually strong for its size: of 14 injected mutations (including a control), **13 were caught**; coverage is a real 100% line/branch/fn/stmt (26/26 stmts, 7/7 branches, 11/11 fns) with no `v8 ignore` escape hatches. There are **no SEV1 defects**. What is wrong is at the contract boundary rather than in the algorithm: (a) `warnOnce` silently burns its dedupe key when no sink is registered yet, contradicting both its own inline comment and the README, and this is the single surviving mutation; (b) the only declared downstream consumer shape (`EdgeContextStoreLogger`) is structurally assignable but semantically incompatible — the message lands in the dedupe-key slot and sinks receive an empty payload; (c) `Object.freeze(args)` is advertised as enforcing handler immutability but is shallow, and the one test that appears to cover it only exercises the array level; (d) the package is currently **inert in production** — `createLogger` is never called outside tests, while `docs/PROGRESS.md` states platforms wire `onError` to it. On the specific self-capture question: **verified safe today, structurally rather than deliberately** — see "Checked and found clean".

## SEV1

None.

## SEV2

### 1. `warnOnce` consumes the dedupe key when there is no sink, permanently swallowing the diagnostic

- **Where:** `packages/logger/src/index.ts:46` (`return true;` in `emit`), consumed at `packages/logger/src/index.ts:80`; contradicted by the comment at `packages/logger/src/index.ts:78-79` and by `packages/logger/README.md:10`
- **What:** `emit()` returns `true` whenever the message passes the *level* gate, regardless of whether any handler exists (`handlers` may be empty). `warnOnce` treats that `true` as "delivered" and adds the key to `warnedKeys`. The inline comment says *"Consume the key only if the warning was actually delivered, so a warning first hit while suppressed can still surface once verbosity is raised"*, and README:10 says *"consumes the key only on actual delivery"* — neither is true for the no-sink case. The stated rationale (a warning suppressed now should still surface later) applies verbatim to a sink that is registered later, so the implementation under-delivers on its own documented intent.
- **Why it matters:** `warnOnce` is the *only* method in this package that any production contract actually uses (`ShimLogger = Pick<Logger,'warnOnce'>`, `packages/integration-shims/src/index.ts:27`), and it fires during integration/provider **activation** — i.e. inside `launch()`. Any ordering where the platform attaches its debug sink after (or alongside) launch means the one-time diagnostic is consumed against zero handlers and can never be emitted again for the lifetime of that logger. The failure is silent and unrecoverable: raising the level later does not help, and there is no key-reset API on the returned `Logger`.
- **Evidence:** Mutation M2 — changed `return true;` → `return handlers.size > 0;` (i.e. the semantics the comment describes) and ran `pnpm --filter @bugsee/logger exec vitest run`: **16/16 still passed → SURVIVED**, proving the behaviour is entirely untested in either direction. Control mutation M1 (`>` → `>=` on the level compare) failed 10 tests, so the harness is sound. Direct probe P1 (temporary test file, since removed): `createLogger('warn')` → `warnOnce('k','…')` with no handler → `addHandler(h)` → `warnOnce('k','…')` again ⇒ `h` call count = **0**.

### 2. Contract mismatch with the declared consumer shape: the message is consumed as the dedupe key and sinks receive an empty payload

- **Where:** `packages/logger/src/index.ts:22` / `:74` (`warnOnce(key: string, ...args: unknown[])`) vs `packages/vercel-edge/src/request-context-store.ts:19-21` (`interface EdgeContextStoreLogger { warnOnce(message: string): void }`), call site `packages/vercel-edge/src/request-context-store.ts:69` (`logger?.warnOnce(ALS_UNAVAILABLE_WARNING)`)
- **What:** `Logger.warnOnce`'s first parameter is the **dedupe key**; the payload is the rest args. The edge consumer declares and calls it as `warnOnce(message)` with no rest args, and its JSDoc (`packages/vercel-edge/src/request-context-store.ts:18`, `packages/vercel-edge/src/launch.ts:110-111`) says *"the launch passes its `debug` logger"* — while `packages/vercel-edge/package.json:31` declares `@bugsee/logger` as a dependency precisely so the real logger can be supplied. TypeScript's structural typing accepts `Logger` wherever `EdgeContextStoreLogger` is required (a `(key, ...args)` signature is assignable to `(message)`), so this compiles with no error.
- **Why it matters:** If/when a platform actually passes the real logger there — which is what the dependency and the JSDoc both anticipate — the "AsyncLocalStorage unavailable" warning is delivered to every sink as `('warn', [])`. The operator sees an empty warn line; the diagnostic text survives only as an invisible dedupe key. This is exactly the silent-degradation path the warning exists to surface.
- **Evidence:** Probe P8 (temporary test file, since removed): declared `interface EdgeLike { warnOnce(message: string): void }`, assigned a real `createLogger('warn')` to it (compiles), called `edge.warnOnce('AsyncLocalStorage unavailable; falling back')` with a recording handler attached ⇒ sink received `[[]]` — one delivery, **empty args**. `pnpm --filter @bugsee/logger exec tsc --noEmit` exits 0 for the assignment, confirming the compiler will not catch this.

### 3. `Object.freeze(args)` is shallow, so the documented immutability guarantee does not hold — and the test that appears to cover it doesn't

- **Where:** `packages/logger/src/index.ts:37` (`Object.freeze(args); // handlers must treat args as immutable; freezing enforces it`), `packages/logger/README.md:12` ("args are frozen"); test `packages/logger/src/logger.test.ts:128-138`
- **What:** `Object.freeze` protects the argument *array* only. Object arguments inside it stay fully mutable, and — unlike the array, which is a fresh rest-args allocation — those objects are **owned by the caller**. A handler that mutates `args[0]` corrupts the caller's own object and changes what every later-registered handler observes. The comment's claim that freezing "enforces" handler immutability is therefore false for the case that matters.
- **Why it matters:** This is a logger for SDK self-diagnostics, so the arguments are live SDK state objects (options, error objects, provider descriptors). A single faulty or third-party sink can mutate SDK internals through the diagnostic channel — the one code path where the SDK is supposed to be purely observational. The `catch {}` at `packages/logger/src/index.ts:42` cannot help, because no exception is thrown. The existing test at `logger.test.ts:128` is titled *"isolates a throwing/mutating handler"* and asserts the second handler still sees `['o']` — but its `evil` handler only calls `args.push(...)`, which the shallow freeze *does* stop, so the test provides false confidence about the deep case.
- **Evidence:** Probe P6 (temporary test file, since removed): `const payload = { secret: 'orig' }`, handler A does `args[0].secret = 'MUTATED'`, handler B records. Result: B saw `[{"secret":"MUTATED"}]` **and the caller's own `payload` was `{"secret":"MUTATED"}`** — no throw, silently swallowed nothing, mutation propagated out of the logger.

### 4. The package is inert in production while `docs/PROGRESS.md` documents platforms as wired to it

- **Where:** `packages/logger/src/index.ts:27` (`createLogger`, the sole runtime export); `docs/PROGRESS.md:18` ("Debug logger (`debug.warn` etc.); platforms route `onError` here.") and `docs/PROGRESS.md:36` ("Platforms wire to `@bugsee/logger`.")
- **What:** No production source file in the repo calls `createLogger`, and no platform package imports `@bugsee/logger` at all. The only two `package.json` dependents are `packages/integration-shims/package.json:28` (which imports `type Logger` only — `packages/integration-shims/src/index.ts:24`, erased at compile time) and `packages/vercel-edge/package.json:31` (which imports nothing from it). The only runtime construction of a logger anywhere is in a **test**: `packages/integration-shims/src/index.test.ts:25`. The documented `onError` → logger wiring does not exist in `@bugsee/node`, `@bugsee/browser`, `@bugsee/bun`, `@bugsee/deno`, `@bugsee/electron`, `@bugsee/webworker` or `@bugsee/vercel-edge`.
- **Why it matters:** Every SDK self-diagnostic that the architecture says should reach the debug channel currently reaches nothing — `onError` defaults to a no-op (`packages/core/src/capture-aggregator.ts:56`) and no platform overrides it with a logger. Provider-start failures, torn capture records and operation-observer failures are therefore invisible to field debugging, and PROGRESS.md misreports the state of a shipped seam. Secondary consequence: `setLevel`/`getLevel`/`addHandler`/`error`/`info`/`debug` have never been exercised by anything but their own unit tests, so their contracts are unvalidated against a real consumer.
- **Evidence:** `grep -rnE "from '@bugsee/(logger|integration-shims)'" --include='*.ts' packages/` (excluding `node_modules`) returns exactly three hits — `integration-shims/dist/index.d.ts:2` (build output), `integration-shims/src/index.test.ts:9`, `integration-shims/src/index.ts:24` (type-only). A dynamic-import grep (`import('@bugsee/logger'…`) returns zero. `grep -rn 'createLogger' --include='*.ts' packages/` outside `packages/logger/src` returns only `integration-shims/src/index.test.ts:9,25`.

## SEV3

### 5. An out-of-contract level fails **open** (maximum verbosity) rather than closed

- **Where:** `packages/logger/src/index.ts:34` (`if (RANK[messageLevel] > RANK[level])`), `packages/logger/src/index.ts:50-52` (`setLevel` performs no validation)
- **What:** `RANK` is a plain `Record` lookup with no fallback. An unrecognised level makes `RANK[level]` `undefined`; `number > undefined` is `false`, so the guard never suppresses and **every** level emits — including `debug`. `getLevel()` then returns the bogus value verbatim.
- **Why it matters:** The failure direction is backwards for a diagnostic channel: a typo or a stale level string flips a logger that may have been deliberately `silent` into full verbosity, and there is no signal that it happened. TypeScript guards the in-repo call sites, but the package ships dual ESM/CJS (`packages/logger/package.json` `publishConfig`) so the type gate is compile-time only. Bounded because the package is `private: true` and has no external callers today.
- **Evidence:** Probe P2: `createLogger('silent')` → `setLevel('verbose' as any)` → `debug('…')` ⇒ handler called **1** time, `getLevel()` returned `'verbose'`. Probe P3b: `createLogger(null as any)` → `debug('…')` ⇒ handler called **1** time. (Note `createLogger(undefined)` correctly yields `'error'` — the ES default-parameter path works.)

### 6. `warnedKeys` grows without bound and has no reset

- **Where:** `packages/logger/src/index.ts:30` (`const warnedKeys = new Set<string>();`), added at `:81`, never deleted or capped; the returned `Logger` (`:49-84`) exposes no clear/reset method
- **What:** Every distinct `warnOnce` key is retained for the lifetime of the logger instance. Nothing caps the set, evicts entries, or lets a caller reset it — not even `setLevel('silent')`.
- **Why it matters:** The in-repo key space is bounded and safe (`shim:${name}`, `packages/integration-shims/src/index.ts:47`), so this is latent rather than live. But the signature is `warnOnce(key: string, …)` with no documented constraint, so a future caller keying on a URL, request id or error message turns a diagnostic helper into a slow leak in a long-lived process (Node server, service worker, edge isolate).
- **Evidence:** Probe P7: 200,000 distinct keys accepted with no eviction and no growth guard; enumerating the returned object confirms the surface is exactly `setLevel,getLevel,addHandler,error,warn,info,debug,warnOnce` — no reset seam.

### 7. `@bugsee/vercel-edge` declares `@bugsee/logger` as a dependency it never imports

- **Where:** `packages/vercel-edge/package.json:31` (`"@bugsee/logger": "workspace:*"`)
- **What:** No file under `packages/vercel-edge/src/` imports the package; the edge tier defines its own structural `EdgeContextStoreLogger` instead (`packages/vercel-edge/src/request-context-store.ts:19`).
- **Why it matters:** A phantom dependency edge in the workspace graph — it makes the logger look wired when it isn't (see SEV2 #4), and it inflates turbo's rebuild/test fan-out for the edge package on every logger change.
- **Evidence:** Repo-wide grep for `@bugsee/logger` across `*.ts` returns no hit under `packages/vercel-edge/src`; the only vercel-edge hit is the `package.json` line itself.

### 8. `__BUGSEE_DEBUG__` gating is claimed by this package but exists nowhere in code

- **Where:** `packages/logger/src/index.ts:1-2` ("the `debug.*` used across the SDK, gated by `__BUGSEE_DEBUG__`") and `packages/logger/README.md:3` (same claim)
- **What:** `__BUGSEE_DEBUG__` appears only in design documents (`docs/design/sdk-design.md:29,285,781,1256-1273,1384,1703,1764`, `docs/dev-environment.md:38-43`) and in this package's own README/header. No `packages/**/src/**` file references it, and neither `packages/logger/tsup.config.ts` nor the shared `tsup.config.base` defines or replaces it.
- **Why it matters:** The header states a build-time gating contract that no build performs, so a reader reasonably assumes SDK debug output is DCE'd from production bundles when nothing of the sort is configured. Cheap to fix in either direction (implement the define, or drop the claim), but leaving it is drift in a file explicitly framed as the contract.
- **Evidence:** `grep -rn '__BUGSEE_DEBUG__' --include='*.ts' --include='*.json' --include='*.js' packages/` (excluding `node_modules`/`dist`) returns **zero** hits.

### 9. Three untested behaviours the implementation deliberately specifies or silently exhibits

- **Where:** `packages/logger/src/index.ts:38` (comment: "a handler that (un)registers handlers mid-emit doesn't affect this delivery"), `packages/logger/src/index.ts:29` + `:56-61` (`Set`-based registry); tests `packages/logger/src/logger.test.ts:140-148`, `:69-77`
- **What:** (a) **Unregister-during-emit** — the snapshot means a handler removed mid-emit *still* receives the in-flight message. The comment specifies both directions but `logger.test.ts:140` only covers the *register* direction; the unregister half has no test. (b) **Zero-handler emit** — no test ever calls `error`/`warn`/`info`/`debug` with an empty handler set, which is the coverage hole behind SEV2 #1. (c) **Duplicate registration** — because `handlers` is a `Set`, registering the same function twice yields one delivery, and the *first* returned unsubscribe removes it for both registrations, silently invalidating the second `off()`. Undocumented and untested.
- **Why it matters:** These are test-strength gaps, not runtime bugs — but (b) is what let SEV2 #1 ship, and (c) is a foot-gun for a future consumer that registers the same bound sink from two call sites and expects refcounted unsubscribe.
- **Evidence:** Probe P5: handler A unsubscribes B mid-emit ⇒ B still received the message (**1** call) — matches the comment, but nothing in the suite pins it. Probe P4: same function registered twice ⇒ **1** delivery; after `off1()` ⇒ still **1** (the second registration is dead). Mutation M2 (SURVIVED) is the direct measurement of gap (b).

## Checked and found clean

- **Self-capture / recursion hazard — verified safe today, and here is exactly how.** `packages/logger/src/index.ts` contains **no reference to `console`, `globalThis`, or any sink at all** (all 85 lines read; zero imports). `createLogger` ships with an empty handler set, so a logger with no registered handler is a no-op by construction. A repo-wide `grep -rn 'addHandler' --include='*.ts' packages/` shows the only `addHandler` call outside this package's own tests is in a **test** (`packages/integration-shims/src/index.test.ts:26`), and it pushes into an array, not `console`. There is therefore **no path today** by which logger output reaches `packages/capture/src/console-interceptor.ts`. Important caveat for future work: this safety is *structural, not guarded*. The console interceptor's `#capturing` re-entrancy flag (`packages/capture/src/console-interceptor.ts`, set around `this.emit('log', …)`) only prevents infinite recursion when a *capture subscriber* logs — it would **not** stop SDK self-diagnostics from being ingested into the customer's bundle if anyone ever registered a `console`-writing `LogHandler`. Nothing in this package documents or enforces that prohibition. Also verified: only two non-test `console.*` mentions exist in the whole SDK source and both are comments (`packages/core/src/capture-aggregator.ts:18`, `packages/node-utils/src/batched-fs-chunk-storage.ts:170`) — the SDK never writes to `console` in production.
- **`@bugsee/core` ↔ logger boundary intact.** `grep -rn 'bugsee/logger' packages/core/` (`*.ts` + `*.json`) returns **zero** hits. Core uses the injected `onError` seam (`packages/core/src/capture-aggregator.ts:22,56,64`; `packages/core/src/capture-drain.ts:11,28`) with a no-op default, exactly as designed. No dependency leak in either direction.
- **Runtime portability: fully clean.** No `import` statements at all, no `node:*`, no DOM identifiers, no `process`/`window`/`fs`, no `globalThis` casts needed because no global is touched. `packages/logger/package.json` declares no `dependencies`. The module is pure data + closures and will behave identically on browser, Node, Bun, Deno, Electron, Cloudflare/Vercel edge and Web/Service Workers, including embedders with no `console` at all.
- **Level ordering and filtering are correct.** `RANK` (`packages/logger/src/index.ts:25`) orders `silent(0) < error(1) < warn(2) < info(3) < debug(4)` and the `>` compare at `:34` suppresses correctly at every boundary; `silent` suppresses even `error`. Mutations M8 (`silent: 0→5`), M12 (`info`/`debug` ranks swapped), M9 (`error()` emitting at `warn`), M11 (`setLevel` no-op) and M13 (default `'error'`→`'debug'`) were **all caught**.
- **Handler-fault isolation is real.** The `try/catch` at `:40-44` genuinely prevents a throwing sink from breaking the caller or starving later sinks — mutation M10 (remove the try/catch) was caught, as was M3 (remove `Object.freeze`) and M4 (drop the `[...handlers]` snapshot). Argument order and passthrough are pinned: M14 (swap `handler(messageLevel, args)` operands) failed 7 tests.
- **`warnOnce` dedupe and level-gate interaction.** M5 (consume the key before emitting) and M6 (drop the `warnedKeys.has` guard) were both caught, so the "suppressed-then-raised recovers" behaviour at `:78-82` is properly pinned for the *level* dimension (only the no-sink dimension is unguarded — SEV2 #1).
- **`addHandler` unsubscribe works.** M7 (make the returned closure a no-op) was caught by `logger.test.ts:69-77`.
- **Coverage and gates are honest.** `pnpm --filter @bugsee/logger exec vitest run --coverage`: 16/16 tests pass, **100% statements (26/26), 100% branches (7/7), 100% functions (11/11), 100% lines**, against thresholds of 100/100/100/≥90 in `packages/logger/vitest.config.ts`. No `/* v8 ignore */` or istanbul pragmas anywhere in `packages/logger/src` — the number is earned, not annotated. `pnpm --filter @bugsee/logger exec tsc --noEmit` exits 0.
- **No test theater found.** Every one of the 16 tests asserts an observable outcome (call counts and exact `(level, args)` payloads); none merely executes code. The 13/14 mutation catch rate corroborates this empirically.
- **No listener/timer leaks.** The package registers no timers, no global listeners, and no process/document hooks; the only retained state is the handler `Set` (explicitly unsubscribable) and `warnedKeys` (SEV3 #6).
- **Repository left untouched.** `git status --short packages/logger` is empty after every mutation and probe run; `diff` against the pre-review backup confirms `packages/logger/src/index.ts` is byte-identical to the original. All probe files were written under the scratchpad and the one temporary in-package probe test was deleted.
