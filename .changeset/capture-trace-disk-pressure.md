Disk-pressure protection for the capture stores, on by default where a durable store exists (as on iOS), and a new `capture` system trace. Below 50 MiB free the on-disk (Node, Bun, Deno, Electron main: `statfs` of the data directory every 5 s) or IndexedDB (browser: `navigator.storage.estimate()` headroom, every 5 minutes, every 30 s under 500 MiB) store stops persisting replay, log and network data; below 10 MiB it persists nothing but a tiny `capture` state entry. The in-memory window is kept either way, so a report built from the live process holds everything the process still has in memory (records waiting for a file that could not be created yet included; with the opt-in worker ring writer, frames still stuck in the ring while the disk is full are not in it) and only a crash loses what was never written (records already on a medium that can no longer be read are not in that report, which is built and delivered anyway). A state is left only 10 MiB above its threshold; a hostile or missing reading never changes the state; a write failing with `QuotaExceededError` / `ENOSPC` (and, for an IndexedDB write, Chromium's `AbortError` / `InvalidStateError`) pins out-of-space until a durable DATA write succeeds again (not until a size reading looks healthy; the probe is a record-sized data write forced past the writer's circuit breaker and backs off so the state cannot flap, and capture resumes within a minute of the disk being freed). `diskProtection: false` opts out. The opt-in `captureDiskSpace` option (canonical key `com.bugsee.option.capture.disk-space`, now shared by the browser and the Node family; the node-only key is gone, the friendly name is unchanged) is only the telemetry: the `capture` trace's `low_disk_space` / `no_disk_space` states and, on Node, `disk_mem_free` / `disk_mem_total`. The `capture` trace (`{state}`: `active`, `blackout`, `low_disk_space`, `no_disk_space`) is written by the browser while its rrweb recorder runs and by Electron main while pixel video runs; never by Node, Bun, Deno, WebViews, Electron renderers or a launch with `replay: false`. Fixes in the batched fs writer: `read()` includes the buffered tail of a failed flush and a chunk seal no longer drops it; the off-thread ring writer reports drain failures instead of swallowing them; a `statfs` that hangs holds one read and starts no more; a short write followed by a failure no longer duplicates data in the ring writer; the IndexedDB store keeps records not yet written (queued or refused) in memory and serves them when the database cannot be read, reopens a closed connection, and times out and releases a read that never answers; the disk-pressure probe is a synchronous write of padding into a file of its own in the part just opened (never queued as a ring frame, never a part of its own), so it leaves no directory, descriptor or late write behind, and a host-side failure of the ring writer can be recovered from. `@bugsee/replay` recorders gain `checkout()` (a fresh full snapshot, used when persistence resumes). New `@bugsee/core` exports: `createDiskPressure`, `withDiskPressure`, `DiskPressureToken`, `isOutOfSpaceError`, the threshold constants, and `diskPressure` / `onDiskWriteError` options on the chunk, file and IndexedDB stores.
