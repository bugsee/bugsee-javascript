New `url` system trace and a sanitizer for the page's own address (C11, C21, C25).

- `@bugsee/browser`, `@bugsee/webview` (and so Electron renderers): the `url` trace, the page's sanitized `location.href` as a held step curve written at start and on every navigation. On by default and independent of the performance extension; new launch options `captureUrl` (default `true`; any non-boolean turns it off and is reported) and `urlSanitizer` (a hook run after the default, its string result written as given, `null` writes nothing, a throw is reported and writes nothing). The navigation source's `navigate` detail gains the absolute `href`, and `createBrowserNavigationSource` an `isolated` mode.
- `@bugsee/protocol`: new `sanitizeLocationUrl`: scheme handling (`data:`/`javascript:`/`vbscript:` reduced to `<scheme>:%3Credacted%3E`, `blob:`/`filesystem:` to their inner origin with no userinfo, `file:` to `file:///.../<last segment>`), and a bounded scan of URLs nested in a query value. The network `sanitizeUrl` is unchanged EXCEPT for two fixes: it recognises the authority (userinfo password) of a `blob:`/`filesystem:` URL, and it cuts a URL fragment at a `#` that starts a `key=` (so a vue-router `#/cb?x=1#access_token=…` is redacted, while a secret containing a literal `#` is still redacted whole); the rest (scheme handling, nested URLs, the extra keys) is `sanitizeLocationUrl` only.
- `@bugsee/nextjs`: the navigation breadcrumb no longer writes the raw `href` (message and data are sanitized).
- `@bugsee/performance`: the transaction name of a URL-detected navigation is sanitized (adapter-supplied route names are kept as given).
- `@bugsee/core`: `urlSanitizer` is kept across `relaunch()` (a redaction hook).
- Review round: the pageload transaction name and resource-timing span descriptions are sanitized too; a `file:` page is named by its last segment. The replay stream's opening Meta `href` is sanitized (`@bugsee/replay`). The page-address denylist adds the exact keys `code`, `state`, `session`, `sid`, `sig`, `ticket` (`key` and `t` are not redacted; the shared substring list already catches `sessionid`, `signature`, `otp`), the hash-router query is scanned, nested URLs and relative return paths are read tolerantly (raw, half-encoded or double-encoded, two levels), raw `https:/u:p@a.com`, backslash and `file:C:\...` forms are normalised like a browser would, and an address over 8192 characters is clipped and marked.
- The navigation source is now shared per window through the carrier (`navigationSourceFor`, used by the `url` trace and the umbrella's navigation transactions; the umbrella now binds it to the window passed to `launch`, not the host global) and its `history` patching is order-safe: it restores only when its wrapper is still outermost, otherwise leaves a pass-through and never removes another library's wrapper (C23).
- `urlSanitizer` results are clipped at 2048 characters; when the hook drops (`null`) or throws, the previous URL stays held.
- Second review round: `file:` pages get the nested-URL scan; nested values use a tolerant per-escape decoder (a stray `%` no longer disables redaction); the fragment's `key=value` pairs are scanned for nested URLs; `code[]`, `code%5B%5D` and `+code` match the exact keys; the 8192 clip runs before any scan and fails closed; the navigation source re-patches `history` after a third party restored or replaced it; the pageload name uses the window passed to `launch`; `@bugsee/core` sanitizes browser script URLs in stack frames (credentials, signed query values).
- Third review round: history patching is reentrancy-guarded (all of a source's wrappers stay live, only the outermost call emits, a throwing navigation emits nothing; stopping unwinds dead wrappers from the top); a second `#` in a fragment is scanned in `sanitizeLocationUrl` and in `sanitizeUrl`; a nested value that is only a fragment is scanned; nested values with a lone surrogate stay encoded; `@bugsee/core` caches sanitized frame URLs and keeps Firefox's ` line N > ...` eval suffix.
- Fourth review round: a fragment is cut only at a `#` followed by `key=` (a secret with a literal `#` is redacted whole, in both sanitizers); an encoded nested value with leading whitespace is scanned; `@bugsee/core` frame URLs are sanitized whole to the first whitespace when the string starts with a scheme (see the sixth round for the eval wrapper and async frames); the history wrapper does not report a not-yet-happened navigation under a deferring third party; the breadcrumb guard also reads `client['addBreadcrumb']()` and a destructured `addBreadcrumb()`.
- Fifth review round: browser script URLs in stack frames are sanitized whole (a `)`, `,` or `:digits` inside a signed query no longer ends the scan) and only Chrome's `eval at f (URL:L:C)` wrapper is scanned for a parenthesised URL; a leading `+` before a nested URL is treated like whitespace; the breadcrumb guard fails closed on indirect references to `addBreadcrumb`.
- Sixth review round (`@bugsee/core` frames): `at async <url>` frames lose V8's `async ` marker so a signed or credentialed URL (and a `file://` path) is sanitized like a synchronous frame; Chrome's eval wrapper handles `blob:`/`filesystem:` URLs and a missing position; any URL the wrapper pattern misses, including one left open by the 4096-character clip, is sanitized to the next whitespace (the clip fails closed); an encoded `%2B` before a nested URL keeps its encoding.
- Seventh review round (`@bugsee/core` frames): Chrome's eval wrapper ends only at `)` + any `)`s + `, ` or the end of the string, so parentheses and commas in a query or fragment no longer close it early; a clip that cuts a URL open drops that URL; a double-encoded leading `%252B`/`%2520` before a nested URL keeps its encoding.
