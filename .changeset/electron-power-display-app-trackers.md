Electron main now records power, display and window telemetry. The power and display domains turn on when `powerMonitor` / `screen` is passed to `launchMain`. The window domain (`window_*`, `renderer_*`) turns on whenever `app` is passed, so existing callers that already pass `app` now get two extra `app` listeners (`browser-window-created`, `web-contents-created`) and these events while `captureSystemEvents` is on; pass `captureWindowEvents: false` to opt out, and `BrowserWindow` only adds windows that already exist. Electron's real `screen` throws until the app is ready: pass it after `app.whenReady()` (a throwing object turns that domain off and is reported, never failing the launch). On `events.system`: `power_suspend`, `power_resume`, `power_lock`, `power_unlock`, `power_ac`, `power_battery` (platform dependent: `lock-screen` and `on-ac` are macOS/Windows, `on-battery` is macOS only); `display_added`, `display_removed` and `display_metrics_changed`; `window_focus`, `window_blur`, `window_show`, `window_hide` (`{ windowId }`) and `renderer_unresponsive` / `renderer_responsive` (`{ webContentsId }`, listened for on `webContents` only so a hang is never recorded twice). The `electron_displays` system trace (`{ displays: [{ id, width, height, scale_factor?, rotation?, internal?, refresh_rate_hz? }] }`, JS-specific name) is written when the display list changes (it is held: a later unreadable list leaves the previous one recorded). Listeners attach only while `captureSystemEvents` / system traces are on and are removed by `client.stop()`. They come from three new per-object domain trackers in `@bugsee/trackers/electron`: `ElectronPowerTracker`, `ElectronDisplayTracker` and `ElectronApplicationTracker`.
