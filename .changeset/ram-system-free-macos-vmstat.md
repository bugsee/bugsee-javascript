`ram_system_free` is now reported on macOS for Node and Bun and Deno. It reads `/usr/bin/vm_stat` asynchronously at most once per 10 seconds, and only while the system-memory stage has a listener. The value is (Pages free + File-backed pages + Pages purgeable) times the page size, the same definition as Electron's `getSystemMemoryInfo` on macOS, so Electron, Node and Bun agree. The spawn uses the absolute path with no shell or arguments, a 2 s timeout and a small output cap. It never overlaps, serves a value for at most two intervals before omitting, and any failure omits the trace and is reported once per failure streak through `onError`. The child is killed when the stage loses its last listener, and an empty read caused by a resumed `execFile` timeout is a silent miss. On Deno the spawn goes through `Deno.Command` (works with only `--allow-run=/usr/bin/vm_stat`, never prompts) and happens only when `Deno.permissions.querySync` already reports it granted; otherwise Deno answers `Deno.systemMemoryInfo().available`, a larger estimate (free + inactive pages) than the vm_stat definition. `current()` on an unarmed stage reads the cache only and never spawns. `@bugsee/trackers/node` gains `createVmStatSampler` and `parseVmStat`, and `ProcessEnv` gains `readsVmStat` (default `true`; `false` opts out), `vmStat` and `vmStatExecFile`, and `@bugsee/trackers/node` also exports `createDenoExecFile` and `denoVmStatGranted`. To opt out, pass `systemTraceProducers: createNodeSystemTraceProducers({ readsVmStat: false })` to `launch`.
