Support OpenTelemetry JS 3.x (issue #94).

OpenTelemetry JS 3.0 removed `@opentelemetry/sdk-trace-base` and replaced it with `@opentelemetry/sdk-trace`, and `@opentelemetry/api` 1.10 widened span attributes to the spec's `AnyValue`. `@bugsee/opentelemetry` and `@bugsee/nextjs` (peer ranges) now declare `@opentelemetry/sdk-trace` (`>=2.9.0`) as an optional peer next to `@opentelemetry/sdk-trace-base` (now `>=1.0.0 <3`); `sdk-trace` exists from 2.9 and exports the same `TracerProvider`. Both stay optional: produce-only users install neither. On OpenTelemetry 3 register the processor with `new TracerProvider({ spanProcessors: [processor] })` from `@opentelemetry/sdk-trace` (on 3.x `sdk-trace` is the only SDK package and `BasicTracerProvider` no longer exists; `sdk-trace` 2.9+ exports the same `TracerProvider`). OpenTelemetry 3 itself needs Node.js 22.15 or newer; `@bugsee/opentelemetry` does not import OpenTelemetry and still runs on the Node versions the SDK supports.

Complex span attributes (OpenTelemetry API 1.10 `AnyValue`) are now handled deliberately. Known limitation, unchanged by this release: SQL literal redaction can be defeated by comments, backslash escapes and dollar quoting shifting its quote pairing (bugsee/bugsee-javascript#109). Consumed scalars and small homogeneous scalar arrays are unchanged (a scalar string is capped at 32 KiB); a byte array becomes base64; a `bigint` becomes a number when exact and decimal text otherwise (it used to reach the transaction as a value JSON cannot serialize); `null`, `undefined`, functions and symbols drop the attribute; nested maps and mixed arrays become a bounded JSON-safe copy that the span sanitizer and `setSpanFilter` now see as a tree, so nested sensitive keys (`user: { password }`, `http.request.headers: { authorization }`) are redacted by default. What remains complex is flattened to a bounded JSON string when the transaction is recorded. The copy never throws and is bounded in work as well as size (leaf, key, node, depth and length caps). A raw byte array that Bugsee exports itself (a `Uint8Array`, `ArrayBuffer` or `DataView` attribute on a span Bugsee produced) is sent as OTLP `bytesValue` (valid base64) when it fits (up to 6144 bytes) and as a `stringValue` carrying the truncation marker when it was cut, so a strict collector never sees a marker inside `bytesValue`; a consumed span's bytes are already a base64 string by then and export as `stringValue`. A URL attribute keeps exporting its href (credentials removed), an Error its name and message, and a Date its ISO string. Arrays of one scalar type that contain null entries pass through unchanged. The default sanitizer now also redacts the current GenAI content attributes (`gen_ai.input.messages`, `gen_ai.output.messages`, `gen_ai.system_instructions`, `gen_ai.tool.definitions`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`). One hostile attribute (a Proxy that throws, a cycle, an enormous string) no longer rejects the whole export batch.

`createBugseeSpanProcessor` now ignores `onEnd` after `shutdown()`.

The same bounding now applies to every span the SDK records itself (`setAttribute`, `recordChildSpan`, `recordExternal`), not only consumed OpenTelemetry spans: the nested redaction walk is only run on a bounded copy, with a shared per-span node and character budget (raw cyclic or branching values used to take seconds to forever). A key too long to keep has its value redacted; a statement cut by a length cap no longer leaves an open SQL literal in the clear, and a map leaf cut inside a token (a JWT after its payload, a `ghp_` prefix) drops the unfinished token, and an unbroken run such as `id_token=<jwt>` keeps its prefix but backs off before the last secret-shaped start (a long map-leaf URL is therefore cut back to `https:`; a top-level string is only cut, because secret-shape scanning does not apply to it, as before: top-level strings, scalar arrays and nested map keys are not shape-scanned); scalar-array attribute values are stored as copies, never aliases of the application's array; and a statement carried as a map or array has its string leaves' literals redacted. `isSensitiveKey` (`@bugsee/protocol`) now normalises its denylist once.

New exports from `@bugsee/protocol`: `lastSecretShapeStart`. New exports from `@bugsee/performance` (some also re-exported from `@bugsee/opentelemetry`): `normalizeAttributes`, `normalizeAttributeValue`, `flattenAttributes`, `stringifyAnyValue`, `safeAnyValue`, `asBytes`, `boundedBase64` and the `MAX_ATTRIBUTE_*` limits.
