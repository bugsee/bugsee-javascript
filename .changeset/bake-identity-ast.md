The Rollup plugin bakes the app version/build (`__BUGSEE_APP_VERSION__` / `__BUGSEE_APP_BUILD__`) into each rendered chunk (Rollup has no `define`; the same detected identity the source-map upload uses, with an exact source map). The chunk is walked on Rollup's own AST, so only real global reads are replaced: a constant name inside a string, template text, comment, regex literal, property name or object key is left alone, a shorthand `{ X }` becomes `{ X: value }`, and a local binding that merely shares the name (a parameter, `var`/`let`/`const`, function, class, import or catch parameter) is never touched. The scope analysis follows the language: a `switch` discriminant and a parameter default are outside the case block and the function body, and a function declared in a block is block-scoped in strict output (`es`, and the `'use strict'` Rollup emits for `cjs`/`iife`/`umd`) but hoisted (Annex B) in sloppy output (`strict: false`). A chunk that mentions a constant but cannot be examined (no parser in the context, a parse failure, or a chunk nested too deeply to walk) is left as Rollup produced it and `this.warn` says, once per output directory per build (again on each watch rebuild), that the identity was not baked; the plugin never fails the build over it.
