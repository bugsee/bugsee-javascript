Adds `bugsee-sourcemaps-doctor`, an offline check of a build output directory (`npx bugsee-sourcemaps-doctor dist`, `--json`, `--strict`, `--deployed`, `--ignore <id>`), and the matching `diagnoseBuildOutput(dir, options)` API with a versioned report (`schemaVersion: 1`). It tells you why a crash from the build would not symbolicate: unstamped bundles or a missing runtime registration, a map whose debugId differs from its bundle's, dangling, hidden or inline source maps, invalid maps and missing `sourcesContent`, duplicate IDs, Subresource Integrity hazards, leftover public maps, development bundles, and the build environment (token source, version, build, `NODE_ENV`; the token value is never printed). Exit 0 ok, 1 warnings with `--strict`, 2 errors. Also: `stamp-files` no longer spreads large file lists onto the call stack (a directory with more than ~125k scripts or maps overflowed it). The Subresource Integrity page scan in the build plugins is now linear (quadratic regexes on pages with thousands of unterminated tags or comments are replaced by an `indexOf` scanner, with a differential test pinning identical results) and pages larger than 8 MiB are skipped.
