'@bugsee/node': patch
---

An uncaught exception or unhandled rejection raised while LOADING a module now names the module that failed, instead of being reported as an error at `node:internal/modules/...` (Node) or with no frames at all (Bun). The failed module becomes the first frame (`import()` or `require()`), and the report description adds the importer, how it was loaded, the error `code` and the CommonJS `require` stack. Node reports a failed ESM/CJS resolution (`ERR_MODULE_NOT_FOUND`, `MODULE_NOT_FOUND`, `ERR_UNSUPPORTED_DIR_IMPORT`, `ERR_PACKAGE_PATH_NOT_EXPORTED`, ...) with the module in the message and in `url`/`requireStack`; Bun (via `@bugsee/bun`, which re-exports this composition) reports a stackless `ResolveMessage` whose `specifier`/`referrer`/`importKind` the SDK now reads. A syntax error becomes a frame at its file, line and column, from Bun's build-error `position` or from the header of Node's stack (present for a CommonJS file and for a missing named export; Node gives no file for a syntax error in a dynamically imported ES module, so that case is unchanged). Bun's stackless missing-named-export SyntaxError names the module from its message. The runtime's own frames are kept after the new first frame, and a caller-supplied frame enricher still runs first.
