# @bugsee/vite-plugin

A Vite plugin that uploads your production source maps to Bugsee, so minified stack traces in crash reports show your original files, lines and function names.

Part of the Bugsee JavaScript SDK (public beta, 0.1.0-beta.x).

Install this package directly as a dev dependency in projects built with Vite (including frameworks that build on Vite). At the end of the build, the plugin stamps each bundle and its source map with a matching debug ID, uploads the maps with the Bugsee command-line tool (installed automatically as a dependency), and deletes the `.map` files from the output so they are not deployed. The SDK reports the debug ID with each crash, and Bugsee uses it to pick the right map.

## Install

```sh
npm install --save-dev @bugsee/vite-plugin
# or
pnpm add -D @bugsee/vite-plugin
# or
yarn add -D @bugsee/vite-plugin
```

## Usage

Source maps must be generated by the build, so enable `build.sourcemap`.

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import { bugseeVitePlugin } from '@bugsee/vite-plugin';

export default defineConfig({
  build: { sourcemap: true },
  plugins: [bugseeVitePlugin({ appToken: process.env.BUGSEE_APP_TOKEN })],
});
```

Without a token (neither `appToken` nor the `BUGSEE_APP_TOKEN` environment variable) the plugin does nothing, so local builds are unaffected.

## Options

- `appToken`: your Bugsee app token. Falls back to `BUGSEE_APP_TOKEN`.
- `appVersion`, `appBuild`: recorded with the uploaded maps. Fall back to `BUGSEE_APP_VERSION` and `BUGSEE_APP_BUILD`.
- `deleteMaps`: delete the `.map` files from the output after upload. Default `true`.
- `stripSourcesContent`: upload maps without embedded source code, if you do not want your source to leave the build machine. Default `false`.
- `failOnError`: fail the build if the upload fails. Default `false`, so a failed upload never breaks a deploy.
- `disabled`: turn the plugin off, for example in development builds.
- `dryRun`: show what would be uploaded without uploading or deleting anything.
