# @bugsee/trackers

The foundation the Bugsee JavaScript SDK builds its domain trackers on.

Part of the Bugsee JavaScript SDK (public beta, 0.1.0-beta.x).

This is an internal building block of the Bugsee SDK, not intended to be installed directly. Install `@bugsee/bugsee` instead.

## What it contains

- The multi-key event emitter (`MultiKeyEmitterBase`, `createMultiKeyEmitter`) and the `EventSubscribable` / `Interceptor` contracts.
- `InterceptorBase`, the base for sources that install a runtime hook only while someone listens.
- `createTrackerRegistry`, the per-window (per key object) singleton registry that trackers are looked up through.

`@bugsee/core` imports this package and re-exports the same public names, so SDK code keeps importing them from `@bugsee/core`.

## Layout

Trackers are the abstraction over system and runtime APIs. The package root is runtime-portable: it never imports DOM, `node:*` or Electron, and receives runtime APIs only through injected env objects and guarded globals. Platform-specific tracker implementations live behind these subpath entries, and only code under them may use that platform's APIs:

- `@bugsee/trackers/browser` (`src/browser/`)
- `@bugsee/trackers/node` (`src/node/`)
- `@bugsee/trackers/electron` (`src/electron/`)

The `./browser` entry exports the `ApplicationTracker` (`applicationTrackerFor`, `resetApplicationTracker`; stages `pagehide`, `visibility`, `state`, `freeze`, `resume`; `online`/`offline` belong to the `ConnectivityTracker` and `orientationchange` to the `UiTracker`), the `PowerTracker` (`powerTrackerFor`, `resetPowerTracker`), the `ConnectivityTracker` (`connectivityTrackerFor`, `resetConnectivityTracker`; stages `online`, `networkInfo`, `state` and `transition`, one per DOM online/offline event with its kind from the event type), the `ProcessTracker` (`processTrackerFor`, `resetProcessTracker`; stages `heap`, `mainThreadLag` (timer drift), `idle` (`requestIdleCallback`), `userIdle` (Idle Detection) and `uptime`, each armed only while it has listeners; the SDK never prompts, so `userIdle` runs only when the `idle-detection` permission is already granted; the SDK's `user_idle_state` trace additionally needs the browser/WebView launch option `captureUserIdle: true`, because a page's own grant is not consent to record and upload idle/locked state), the UI/display `UiTracker` (`uiTrackerFor`, `resetUiTracker`: orientation, screenSize, viewport, visualViewport (pinch zoom and pan), colorScheme, reducedMotion, displayMode, frameRate), the `StorageTracker` (`storageTrackerFor`, `resetStorageTracker`; an approximate origin quota estimate, not device free space: browsers may pad `usage`, and `quota` can roughly reveal the device's disk size, so treat it as potentially identifying), the `EnvironmentTracker` (`environmentTrackerFor`, `resetEnvironmentTracker`; language, time zone, and, only when a consumer sets `observeHints` / `queryPermissions`, environment hints and Permissions API states queried without ever prompting; the private-browsing heuristic runs when `detectPrivateMode` is set (the browser launch sets it by default; opt out with `captureEnvironmentHints: false`) and is never reported as a certainty) and `hostRead`; the `./electron` entry exports the Electron main-process domain trackers, with every Electron object injected structurally and never imported: the `ElectronProcessTracker` (`electronProcessTrackerFor`, `resetElectronProcessTracker`; stages `appMetrics`, `childProcessGone` and a once-only GPU read), the `ElectronPowerTracker` (`electronPowerTrackerFor`, keyed on `powerMonitor`; stages `suspendResume`, `lockScreen`, `powerSource` and a live `current('powerSource')`), the `ElectronDisplayTracker` (`electronDisplayTrackerFor`, keyed on `screen`; stages `displayAdded`, `displayRemoved`, `displayMetricsChanged`, `displays` and a live `current('displays')`) and the `ElectronApplicationTracker` (`electronApplicationTrackerFor`, keyed on `app`; stages `windowFocus`, `windowVisibility` and `rendererResponsiveness`, which listens on `webContents` only), plus `mapGpuInfo` and `mapDisplay`. Each stage attaches its Electron listeners only while it has a subscriber and removes them when the last leaves. Its API is internal and may change between releases.

The `./node` entry is shared by Node, Bun and Deno and exports the process `ProcessTracker` (`processTrackerFor`, `resetProcessTracker`; a per-process singleton, keyed on the `process` object by default). Its eight stages (`memory`, `systemMemory`, `cpu`, `eventLoop`, `utilization`, `gc`, `v8Heap`, `memoryLimit`) are each armed only while they have listeners, behind one shared sampling timer. The `utilization` stage reports `{ utilizationPercent }` (percent 0-100, one decimal, of the window the loop was not idle; `createGuardedElu` converts perf_hooks' 0..1 fraction). The `gc` stage feeds the `gc` system event (not a trace). A stage the runtime cannot honestly measure emits nothing rather than zero (event-loop utilization on Bun/Deno is dropped by its own tell, idle and active both zero; the event-loop delay histogram on Deno, the GC observer on Bun/Deno, and the V8 heap on Bun are gated by the `measures*` flags the platform packages pass in). `systemMemory.free` is memory available to new work in bytes (Android `availMem`): Electron `process.getSystemMemoryInfo()` or Deno `systemMemoryInfo().available` on macOS first, then `/proc/meminfo` MemAvailable where `readsProcMeminfo` is true (Bun only), then, on macOS only, a rare async `/usr/bin/vm_stat` read (free + file-backed + purgeable pages, the same definition as Electron's `getSystemMemoryInfo`; absolute path, no shell, 2 s timeout, at most one read per 10 s, value served for at most two intervals, single in-flight, killed when the stage loses its last listener, failures omit and are reported once per streak; opt out with `readsVmStat: false`, e.g. `launch(token, { systemTraceProducers: createNodeSystemTraceProducers({ readsVmStat: false }) })`; on Deno it spawns via `Deno.Command` only when the `run` permission for `/usr/bin/vm_stat` is already granted (never prompting), else `Deno.systemMemoryInfo().available`, a larger free+inactive estimate; an unarmed `current()` reads the cache only; a hung child can delay process exit by up to the 2 s timeout; macOS is mostly a developer platform and the spawn happens only while the stage has a listener), then `os.freemem()` (not on macOS, where it is free pages only). It is omitted whenever no source is plausible. Inside a container it is the host's figure; the cap is `process_memory_limit`. The CPU stage has no start value: it reports from the first tick. Seams merge and are never dropped: a later launch that omits `scheduler` or `onError` keeps the previous launch's, and building a producer set already rebinds the shared tracker, so tests that inject fakes need a private `key` or `resetProcessTracker()`. It also exports the guarded runtime sources it is built from (`createGuardedEventLoopSource`, `createGuardedElu`, `createGcSource`, `createV8HeapReader`, `createMemoryLimitReader`, `createSystemFreeReader`, `createElectronMemoryReader`, `createDenoMemoryReader`, `createProcMeminfoReader`, `parseMemAvailable`).

The `./node` entry also exports the disk `StorageTracker` (`storageTrackerFor`, `resetStorageTracker`; one singleton per resolved data directory, so launches over the same directory share a tracker and launches over different directories never affect each other; a launch without a data directory gets the shared inert `process`-keyed tracker, and an explicit `key` overrides, for tests) behind the opt-in `disk_mem_free` / `disk_mem_total` traces. Its one stage, `disk` (`{freeBytes, totalBytes}`), reads the volume of the launch's data directory with `fs.promises.statfs` (not `/` or the working directory) at once when a listener arrives and then on its own unref'd 5 s timer, and does nothing while no one listens, when there is no data directory, or when the runtime has no `statfs`. An unreadable or unsane reading emits nothing (a full disk is a true 0 free), and failures are reported once per failure streak. Within one directory's tracker, `onError`, `scheduler` and `statfs` are latest-launch-wins, an omitted seam keeps the earlier one, and a changed seam is applied (and re-read) immediately. Only the merged seams survive the last unsubscribe; the last reading does not.
