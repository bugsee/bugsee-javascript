# @bugsee/webpack-plugin

A Webpack plugin that uploads your production source maps to Bugsee, so minified stack traces in crash reports show your original files, lines and function names.

Part of the Bugsee JavaScript SDK (public beta, 0.1.0-beta.x).

Install this package directly as a dev dependency in projects built with Webpack. After the build output is emitted, the plugin stamps each bundle and its source map with a matching debug ID, uploads the maps with the Bugsee command-line tool (installed automatically as a dependency), and deletes the `.map` files from the output so they are not deployed. The SDK reports the debug ID with each crash, and Bugsee uses it to pick the right map.

## Install

```sh
npm install --save-dev @bugsee/webpack-plugin
# or
pnpm add -D @bugsee/webpack-plugin
# or
yarn add -D @bugsee/webpack-plugin
```

## Usage

Source maps must be generated by the build, so set `devtool`.

```js
// webpack.config.js
const { bugseeWebpackPlugin } = require('@bugsee/webpack-plugin');

module.exports = {
  devtool: 'source-map',
  plugins: [bugseeWebpackPlugin({ appToken: process.env.BUGSEE_APP_TOKEN })],
};
```

With ES modules, use `import { bugseeWebpackPlugin } from '@bugsee/webpack-plugin';`.

Without a token (neither `appToken` nor the `BUGSEE_APP_TOKEN` environment variable) the plugin does nothing, so local builds are unaffected.

## Options

- `appToken`: your Bugsee app token. Falls back to `BUGSEE_APP_TOKEN`.
- `appVersion`, `appBuild`: recorded with the uploaded maps, and baked into your bundle so the Bugsee SDK in your app reports the same release without you passing `appVersion` to `launch()`. The version comes from the option, then `BUGSEE_APP_VERSION`, then the `version` in the nearest `package.json` at or above your bundler's project directory (Vite `root`, webpack `context`; not the repository root, so a monorepo app reports its own version). If that nearest `package.json` has no version, there is none: a workspace or parent version is not adopted. Blank or whitespace-only values count as unset. The build comes from the option, then `BUGSEE_APP_BUILD`, then the commit id your CI provides (`GITHUB_SHA`, `VERCEL_GIT_COMMIT_SHA`, `CI_COMMIT_SHA`, `CIRCLE_SHA1`, `BUILDKITE_COMMIT`, `SOURCE_VERSION`, `RENDER_GIT_COMMIT`, `COMMIT_REF`, `CF_PAGES_COMMIT_SHA`, `GIT_COMMIT`). When nothing is found the upload uses `0.0.0` / `0` and nothing is baked in. The values are baked in even with no app token; `disabled: true` turns it off. A `DefinePlugin` you add yourself for `__BUGSEE_APP_VERSION__` / `__BUGSEE_APP_BUILD__` is never overridden, and it is what the upload is recorded with too when it is a plain string (`JSON.stringify('2.4.1')`); if it is an expression the plugin cannot read, the upload uses only an explicit `appVersion` / `appBuild` (or `BUGSEE_APP_*`), never a detected one, and the plugin warns until you pass one. webpack 4 has no `DefinePlugin` the plugin can reach, so nothing is baked there: the upload records only an explicit value (or your own `DefinePlugin` string), never the detected one the bundle would not report, and the plugin warns; pass the same explicit value to `launch()`.
- `deleteMaps`: delete the `.map` files from the output after upload. Default `true`.
- `stripSourcesContent`: upload maps without embedded source code, if you do not want your source to leave the build machine. Default `false`.
- `failOnError`: fail the build if the upload fails. Default `false`, so a failed upload never breaks a deploy.
- `disabled`: turn the plugin off, for example in development builds.
- `dryRun`: show what would be uploaded without uploading or deleting anything.
